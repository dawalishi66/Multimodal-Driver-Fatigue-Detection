# UL-DD CAN 数据审计 v1

本审计对应 `configs/can_preprocessing_v1.json` 和本地首次完整预处理。真实 metadata、NPZ 与含本机路径的运行清单保存在数据集目录，不提交 GitHub。

## 数据范围与结果

- `Labels.csv` 含 35 个 session，每个 session 有 10 个 240 秒 KSS 标签。
- `CSV_Files.zip` 含 34 个 Telemetry session；项目固定驾驶员范围内有 29 个带标签候选 session、16 名驾驶员。
- 固定驾驶员范围内实际存在 28 个 Telemetry 文件，共 4,014,240 条原始记录；单文件 128,640 至 144,000 条。
- `A_A` 有标签但没有 Telemetry，保留为 80 条 `SOURCE_TELEMETRY_MISSING` 记录。
- B、I、M 共 6 个 session 不在团队固定 split 中，不擅自分配到 train/val/test。
- 共建立 2320 个 30 秒候选窗口，1933 个有效，307 个时钟待确认，80 个源文件缺失。
- 290 个 240 秒父区间中，238 个具备完整 8 个有效窗口：train 159、val 41、test 38。
- 输出 1933 个 NPZ，特征均为 `float32[300,9]`；完整目录约 20.4 MiB。
- 公共结构验证和 CAN 专用验证均为 `PASS`。

## 尚未完成的验收

- 当前以每个 Telemetry 文件首个 capture timestamp 作为 CAN 内部采集零点。正式 Video+CAN 配对前，仍需视频负责人用视频 metadata 交叉确认共同零点。
- 时钟异常后的 307 个窗口不能进入当前训练 cohort。若之后取得采集日志或视频帧级证据，应提交新的映射版本，不能直接覆盖 v1。
- 特征没有标准化。单模态训练和 MulT 训练只能用 train split 拟合归一化参数。
- 本审计没有训练 CAN 单模态基线，也没有使用 test 进行模型选择。
